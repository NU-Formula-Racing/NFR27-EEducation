# Education Firmware
Firmware for the NFR electrical education board (STM32U535CCU). The project is generated by STM32CubeMX (`eeducation.ioc`) and built with CMake.

## Repo layout
| path | what it is |
| --- | --- |
| `Core/` | CubeMX-generated startup, `main.c`, peripheral init |
| `Labs/` | lab code, one folder per lab (`Lab_1` ... `Lab_4`) |
| `c-fsm/` | [c-fsm](https://github.com/Evan-Bertis-Sample/c-fsm) git submodule, single-header finite state machine library |
| `Drivers/` | ST HAL and CMSIS (generated, don't edit) |
| `cmake/` | toolchain files and CubeMX-generated CMake |
| `eeducation.ioc` | CubeMX project (pinout, clocks, peripherals) |

## Setup
### Install the following
- [vscode](https://code.visualstudio.com/)
    - [stm32cubeide for vscode](https://marketplace.visualstudio.com/items?itemName=stmicroelectronics.stm32-vscode-extension) (installs CMake Tools and the other extensions it needs)
- git
- [stm32cube programmer](https://www.st.com/en/development-tools/stm32cubeprog.html) (optional, only needed for flashing without vscode or if the board needs a full chip erase)
- [stm32cubemx](https://www.st.com/en/development-tools/stm32cubemx.html) (optional, only needed to change `eeducation.ioc`)

The vscode extension installs cmake, ninja, and the arm compiler.

On Windows, the ST-LINK USB driver comes with stm32cube programmer. If the ST-LINK isn't detected, install [ST-LINK driver](https://www.st.com/en/development-tools/stsw-link009.html).

### Clone the repo
Make sure to configure github for ssh, for more information check [here](https://docs.github.com/en/authentication/connecting-to-github-with-ssh).

This repo uses a git submodule (`c-fsm`), so clone with `--recurse-submodules`:
```sh
git clone --recurse-submodules git@github.com:NU-Formula-Racing/NFR27-EEducation.git
cd NFR27-EEducation
```

If you already cloned without it, `c-fsm/` will be empty. Fix it with:
```sh
git submodule update --init --recursive
```

### Hardware connection
- use the flash harness with stlink and 6 pin output
- make sure the square mark on the flash harness on the connector is facing pin 1 (facing the microcontroller)
- connect stlink to your laptop, make sure the blue light on the stlink is active

## Pick a lab
There are four labs, one per piece of hardware: LED, IMU, ADC and CAN. Start with the [labs overview](Labs/README.md), which links each lab's handout. Without a board, the same lab code runs on the [simulator](Labs/README.md#simulator).

Labs live in `Labs/Lab_N/`. Choose which one runs by uncommenting its call in `Core/Src/main.c` (only one at a time), then pick the part with `#define LAB_N_PART` at the top of `Labs/Lab_N/lab_N.c`:
```c
  /* USER CODE BEGIN 2 */
  lab_1();
  // lab_2();
  // lab_3();
  // lab_4();
```
- any new `.c` files you add under `Labs/` are picked up by the build automatically (you may need to re-run `CMake: Configure` for them to show up)
- if you add a new header, include it in `Labs/labs.h`
- `Labs/Lab_1` ... `Labs/Lab_4` are already on the include path. If you make a new folder, add it to `target_include_directories` in `CMakeLists.txt`

## Building and flashing in vscode
### First time setup
1. open the repo folder in vscode (**File > Open Folder**, pick the `NFR27-EEducation` folder itself, not a parent folder)
2. when the stm32cube extension asks to configure the project, accept it. This installs the arm toolchain, `cube-cmake`, and ninja the first time, so it can take a few minutes
3. when cmake asks for a configure preset, pick `Debug`
    - if it doesn't ask, open the command palette (`Ctrl+Shift+P` / `Cmd+Shift+P`) and run `CMake: Select Configure Preset`, then `Debug`
4. wait for the configure to finish (watch the **Output** panel, `CMake/Build` channel). It should end with `Build files have been written to: .../build/Debug`

### Build
- click **Build** in the bottom status bar, press `F7`, or run `CMake: Build` from the command palette
- the output firmware is `build/Debug/eeducation.elf`
- compiler errors show up in the **Problems** panel (`Ctrl+Shift+M` / `Cmd+Shift+M`), click one to jump to the line
- if the build gets into a weird state (e.g. after switching branches), run `CMake: Delete Cache and Reconfigure`, then build again

### Flash and debug
1. plug in the stlink and connect the harness to the board (see [Hardware connection](#hardware-connection))
2. open the **Run and Debug** view (`Ctrl+Shift+D` / `Cmd+Shift+D`)
3. the first time, click **create a launch.json file** and choose **STM32Cube: STLink GDB Server**. This creates `.vscode/launch.json` (it's gitignored, so everyone does this once)
4. press `F5` (or the green ▶ in the Run and Debug view). This builds, flashes the board over SWD, and stops at the start of `main()`
5. use the debug toolbar at the top:
    - `F5` continue
    - `F10` step over
    - `F11` step into
    - `Shift+F11` step out
    - `Ctrl+Shift+F5` / `Cmd+Shift+F5` restart
    - `Shift+F5` stop
6. click left of a line number to set a breakpoint. Hover variables or use the **Variables** / **Watch** panels to inspect them. The **Peripherals** (XPERIPHERALS) panel shows register values

The program stays flashed after you stop debugging. Unplug and replug the board (or press reset) and it runs on its own.

### Flashing without the debugger (stm32cube programmer)
Use this to load a build without debugging, or when the debugger can't connect.

GUI:
1. open stm32cube programmer, select **ST-LINK** on the right, then **Connect**
2. go to **Erasing & Programming** (second icon on the left), browse to `build/Debug/eeducation.elf`
3. check **Verify programming** and **Run after programming**, then **Start Programming**
4. **Disconnect** when done, otherwise vscode can't use the stlink

CLI (`STM32_Programmer_CLI` is in the programmer's `bin/` folder):
```sh
STM32_Programmer_CLI -c port=SWD -w build/Debug/eeducation.elf -v -rst
```

## Using the c-fsm submodule
`c-fsm/fsm.h` is a single-header (stb-style) library. In exactly one `.c` file, define the implementation before including it:
```c
#define FSM_IMPL
#include "fsm.h"
```
Other files only `#include "fsm.h"`. See `c-fsm/README.md` and `c-fsm/examples/` for usage.

Don't edit `c-fsm/`, it belongs to the upstream repo.

## Changing the hardware config (CubeMX)
Pins, clocks, and peripherals are set in `eeducation.ioc`. To change them, open it in stm32cubemx (or from the stm32cube extension) and regenerate code.

Regenerating rewrites `Core/` and `cmake/stm32cubemx/`. Only code between `/* USER CODE BEGIN ... */` and `/* USER CODE END ... */` comments is kept, so put any edits to generated files inside those blocks. `CMakeLists.txt` at the root is not overwritten.

## Troubleshooting
| problem | fix |
| --- | --- |
| `c-fsm/` is empty or `fsm.h` not found | `git submodule update --init --recursive` |
| `cube-cmake` not found / configure fails right away | let the stm32cube extension finish installing its bundles, then reload the window (`Developer: Reload Window`) |
| no configure presets / cmake asks for a kit | make sure you opened the repo root (the folder with `CMakePresets.json`) |
| `No ST-LINK detected` | check the usb cable and the stlink light, close stm32cube programmer if it's connected, try another usb port, (Windows) install the ST-LINK driver |
| `Target not found` / `Could not connect to target` | check harness orientation (square mark at pin 1), make sure the board is powered |
| can't connect after flashing bad code | in stm32cube programmer set **Mode: Under reset**, connect, then **Full chip erase** and reflash |
| new `.c` file isn't compiled | run `CMake: Configure` again |
